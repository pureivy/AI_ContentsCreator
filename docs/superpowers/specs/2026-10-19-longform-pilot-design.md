# 롱폼 시범 1편 — 과실나무 겨울 전정 총정리 (2026-10-19)

## 의도와 이유

사장님 질문: "10분짜리 롱폼 영상 만들 수 있어?" → 지금 시스템은 세로 숏폼(1080×1920)만 만든다.
자동화 전에 **손으로 한 편** 만들어 품질·비용·렌더 시간을 확인하고, 그 뒤 자동화 여부를 정한다.

주제는 데이터로 정했다(사장님 지시: "블로그 글과 숏폼 조회수 기반 최다 조회 글을 바탕으로").
블로그+숏폼(유튜브·인스타·페북·네이버 클립) 최신 조회 합산 상위 15편 중 7편이 전정·가지치기.
1위 글(주지 3개 선정, 28,268)을 뼈대로 상위 전정 글을 장(章)으로 엮는다 — 사장님 선택.
배롱나무 겨울전정(2위)은 보관소 실촬영 0초이고 과실나무가 아니라 뺐다 — 사장님 선택.

## 목표

- 9~11분 가로 16:9(1920×1080, 30fps) mp4 한 편.
- **결과물은 mp4 파일로 사장님께 먼저 보여준다**(유튜브 업로드 안 함) — 사장님 결정.
- 화면 대부분을 보관소 실촬영으로 채운다.
- 만든 뒤 보고: 총 소요 시간, API 비용(ElevenLabs 글자 수, LLM), 렌더 시간, 아쉬운 점.

- I2V 영상 생성, direct MG(HTML 모션그래픽 에이전트) 단계.

## 구성 (장 순서는 사장님 승인)

1. 들어가며 — 왜 잎 진 휴면기에 자르나 (~50초)
2. 어린 묘목 주지 3개 고르기 (~3분, 뼈대)
3. 매실 — 굵은 가지는 낙엽 후 휴면기에 (~1분)
4. 자두 — 높이는 손이 정한다 (~1분)
5. 감나무 — 잎 진 뒤로 미루는 이유 (~1분 30초, 실촬영 141초로 넉넉)
6. 블루베리 — 잎 진 뒤엔 늙은 원줄기를 밑동에서 (~1분)
7. 마무리 — 자르면 안 되는 가지 세 가지 + 정리 (~2분)

**수종 장은 짧게, 일반 장(1·2·7)을 길게** — 사장님 결정(실촬영 부족: 자두 22초·블루베리 37초·매실 41초+설중매 26초).
수종 장에서 영상이 모자라는 부분은 도표·목록 카드로 채운다. 일반 장은 어느 과실나무 영상이든 쓴다.
장별 분량은 빌더 재량(합계 9~11분 — **런타임이 우선**).

장 3·6 방향 전환(Claude 판단, 원문 근거): 블루베리 원문(`data/sessions/ad3ce06c01da/05_final_content.json`)은
"새 줄기·마른 가지만"을 잎 있는 9월 규칙으로, 낙엽 후엔 늙은 회색 원줄기를 밑동에서 고르고 수형을 잡는다고 쓴다.
겨울 편이므로 낙엽 후 규칙을 가르친다. 매실도 원문 표의 '낙엽 후 휴면기' 칸을 쓴다.
"가을에 해 둔 것 → 이제 남은 것" 흐름은 연결 문장으로 짧게만.

## 대본

- 분량: 공백 제외 약 3,800~4,200자(Claude 판단). 실측 숏폼 낭독 ≈5.6자/초(공백 제외, 속도 1.2) 기준으로 10분 안팎.
  낭독 속도는 .env `ELEVENLABS_SPEED=1.2`(사장님 결정, 전 작가 공통)를 그대로 쓴다 — 롱폼이라고 낮추지 않는다.
  첫 TTS 몇 장 뒤 실측해 분량을 조정. 원문 합계(~15,000자)를 **줄이는** 작업이지 늘리는 작업이 아니다.
- 잎 달린 영상(보관소 전부 9~10월 촬영)과 "잎 진 뒤" 내용의 어긋남은 대본으로 푼다 — 사장님 결정.
  "지금은 잎이 달려 있지만, 잎이 지면 …"처럼 지금 모습에서 겨울 작업을 예고하는 말투.
- 원문 문장·사실만 쓴다. 새로 쓰는 것은 장 사이 연결 문장과 도입·마무리뿐.
- 시기 고치기: 매실·블루베리 글의 "9월" 맥락을 겨울 휴면기 시점으로 바꾼다. 원문이 휴면기 시점을 따로 말하지 않으면 시기를 단정하지 말고 원문에 있는 시기만 쓴다.
- 문체: 블로그 STE 문체 규칙(메모리 blog-style-ste-rules) 따름. 'A가 아니라 B' 남발 금지(AI 티 기준선).
- 검사:
  - `timingParityIssues(원문합본, 대본)` (`src/content/timingParity.ts:199`) — 원문에 없는 월·날짜·수치 0건.
  - `factGateBlog` (`src/content/factGate.ts:394`) 에 6편 원문을 근거로 넣어 대본 판정. 근거 없음 0건.
- 대본을 렌더 전에 따로 승인받지 않는다. mp4와 함께 대본 txt를 옆에 둔다(Claude 판단).
- 대본 형식: 장 → 문장 단위 세그먼트 배열 JSON. 세그먼트마다 `narration`, 선택 `card`(카드 종류·데이터), `footage`(수종 힌트).

## 목소리·자막

- 숏폼과 같은 ElevenLabs 경로 `synthesize` (`src/voice/tts.ts:178`), .env 의 기본 목소리. 한 세그먼트 = 한 번 호출(문장 1~2개). 앞뒤 문장을 previous_text/next_text 로 넘겨 억양을 잇는다.
- 수종명 발음 확인은 `ttsCheck`(mlx_whisper) 그대로 사용.
- 자막: 숏폼과 같은 구절 분할(`splitPhrases`) + 세그먼트 안 글자수 비례 배분. 세그먼트가 짧아 비례 배분으로 충분.
- 장 시작마다 장 제목 카드(2~3초).

## 화면

- 보관소 영상은 **거의 전부 세로**(98개 중 96개가 세로로 재생). 가로 화면 처리:
  - **기본안(빌더 판단): 좌우 분할** — 왼쪽(또는 오른쪽)에 세로 영상 패널(높이 1080, 폭 ~608), 반대편에 장 제목·자막·카드. 영상 전체가 잘리지 않고, 남는 공간이 정보 영역이 된다.
  - 대안: 흐린 배경 확대 + 가운데 세로 영상(필러박스). 레이아웃 검토 때 사장님께 비교 화면 제시 가능.
- 원본 영상 소리는 끈다(낭독만).
- 수종 매칭: 장 수종 영상 우선(감나무 141초, 매실 41초+설중매·설중매나무 26초 — 매실 품종이라 매실로 셈(Claude 판단), 자두 22초, 블루베리·블루베리나무 37초), 부족분은 다른 과실나무(사과·배·대추·석류·살구·체리 등 약 15분 분량)를 "일반 과실나무 장면"으로. 다른 수종 영상을 특정 수종 이름 위에 쓰지 않는다 — 장 1·2·7(일반 과실나무 장)에서만 섞는다.
- 한 파일을 여러 구간으로 나눠 쓰는 것 허용(롱폼은 숏폼 규칙 "한 편 한 파일"과 다름). 같은 구간 반복 금지.
- 카드: 기존 Remotion 카드(StatCountUp·ListReveal·CompareCard·TakeawayCard 등)를 가로 정보 영역에 맞게 다시 배치. 표("자를까 말까 헷갈리는 가지")는 CompareCard/ListReveal 로.
- AI 그림: 원칙적으로 안 씀. 꼭 필요하면 도표·일러스트풍만.
- 배경 음악: 없음(숏폼과 동일) — 빌더 판단으로 바꾸지 않는다.

## 만드는 방식 (코드)

- 새 Remotion 컴포지션 `LongForm` (1920×1080, 30fps) — `remotion/LongForm.tsx` 신규, `Root.tsx` 에 등록만 추가. AutoShorts 는 건드리지 않는다.
- 카드 컴포넌트가 세로 고정값(px)을 쓰므로, 가로용은 새 래퍼/변형으로 만들고 기존 컴포넌트 기본값은 바꾸지 않는다.
- 일회성 스크립트 `scripts/longform/` 아래: 원문 수집 → (대본 JSON은 사람/Claude가 작성) → 검사 → TTS → 영상 구간 배정·자르기 → props → renderMedia.
- 출력: `data/longform/pilot-2026-10-19/` 에 `final.mp4`, `script.json`, `script.txt`, `subtitles.srt`, `footage.json`(사용 구간), `report.md`(시간·비용).
- 렌더 옵션은 숏폼 `RENDER_OPTS` 재사용(gl angle 등). 18,000프레임 — 백그라운드 실행.
- 기존 테스트(`pnpm test`) 통과 유지.
